## 一、总体结论

**方案可行，建议放行**，但 P0 清单中存在 **2 处事实性错误**、工程配合部分有 **3 处需要调整**。这些均为文字层面的修订，不动摇整体设计方向（去实验室化、情感陪伴、分层批次）和实施节奏。

开工前必须先完成第三节所列的修正，否则第 1 批就会做错两件事：把一个不存在的 FAB 当 bug 去修，以及按一个本身不过 WCAG AA 的色值去校准对比度。

## 三、必须修正的两处事实性错误

### 错误 1：训练页没有 FAB，"被遮挡的 +"是内联按钮

**核实过程：**

- 全代码库不存在任何 `position: fixed` 的悬浮按钮。fixed 元素仅有：底导航（components.css:60）、toast（:309）、confirm-sheet（:730）、settings 面板（:650）、skip-link（base.css:204）。
- 截图右下角被底部导航部分遮挡的白色 "+" 圆钮，实际是「本周训练安排」列表中"今日"项上的**内联按钮**（app-render.js:704，`data-apply-today-plan`，class `mini-icon-button`），用于"套用今日训练"。
- `.app-surface` 有 `104px + env(safe-area-inset-bottom)` 底部内边距（base.css:187），用户上滚即可完整露出该按钮——这是固定导航下的**正常滚动遮挡**，不是死 bug。

**对方案的影响：**

- 修复动作（移除该按钮）**碰巧仍然成立**——它与 hero 卡里的「套用计划」按钮（app-render.js:655，同一个 `data-apply-today-plan`）功能完全重复，删冗余合理。
- 但定性错了：不是"z-index/布局冲突 bug"，也不是"与首页记录入口重复的第三套记录入口"（它是套用计划入口，不是记录入口）。

**修订建议：** 将 P0-1 改写为——

> 移除周计划列表"今日"项上与 hero「套用计划」功能重复的内联 "+" 按钮（app-render.js:704）。属冗余入口清理，非 bug 修复。若要求初始视口完全无遮挡，需另行评估列表卡片的整体布局节奏，单纯删按钮不解决其他列表项的滚动遮挡。

### 错误 2：对比度论断和建议色值都不过关

**事实核查：**

- `--muted-2 #8a9699` 在全站**只用作背景色**（同步指示点 components.css:41、餐点圆点 pages.css:954），从不用作文字色；辅助文字实际使用的 token 是 `--muted #65747b`（31 处）。
- 方案建议的替换值 `#6f7c80` 本身就过不了 WCAG AA（小字号正文要求 4.5:1）：

| 颜色 | 纸色底 #f2f0e9 | 纸白底 #faf9f4 |
|------|------|------|
| 现状 `--muted` #65747b | 4.25（勉强不足） | 4.60 ✓ |
| 方案建议 #6f7c80 | **3.78 ✗** | **4.09 ✗** |
| **本评审建议 ≈#5f6b70** | **≈4.9 ✓** | **≈5.3 ✓** |

**修订建议：** P0-4 对比度部分改为——

- 文字色走 `--muted`：`#65747b` → **`#5f6b70`**（两档底色均稳过 AA）；
- `--muted-2` 保持背景用途不变，无需改动；
- 字号下限 0.75rem 部分属实（36 处违规），照方案执行。

## 四、工程配合部分的修正（3 处）

1. **axe-core 接入位置错了**：方案写"接入 `npm run check` 链路"，但 check 是纯 `node --check` 语法检查 + 数据校验脚本，不启动浏览器；axe-core 需要 DOM，应挂在 Playwright 用例内（`tests/` 下新增 a11y spec，跑在 `test:e2e` / `verify` 链路中做断言）。
2. **reduced-motion 截图基线时机错了**：当前全站几乎没有动画，第 1 批（方案第六部分第 1 条）就补该基线只会得到与现状相同的截图，属于无效基准。应改为在第 2 批（页面切换过渡）、第 4 批（多巴胺时刻）动画实际落地时同步补充。
3. **行数数字过时**（小问题）：app-render.js 实际 1037 行、app-actions.js 实际 1214 行（方案写 1103/1276）。结论不受影响，顺手更新即可。

**附带发现：** 视觉测试确认为视口截图（非 fullPage），遮挡判定有效。但"三档视口（320/390/430）"目前**只有 home 页齐全**，其余页面仅 390×844 一档——扩档工作（工程配合第 1 条）落地时应顺手补齐其他页面的 320/430 基准。

## 五、核实后确认成立的部分

以下内容经代码核验**全部成立，照方案执行**：

- **零依赖约束**：纯 CSS 开关（appearance: none 滑块）、SVG 折线 touch tooltip（自实现）、count-up 动画（requestAnimationFrame）、自实现下拉刷新，均可零依赖实现，符合"不引运行时依赖"红线；
- **`navigator.vibrate(10)` 在 iOS 静默失败无副作用**的判断正确；
- **批次划分合理**：P0 全是低成本高确定性修复，P2 明确标可选，回退成本低；
- **"每批跑 `npm run verify` + 更新视觉回归基准"** 与现有 package.json 的 `verify` 脚本链路完全对得上；
- **交互态收敛到 app-state UI 切片**的约束符合现有架构风格。
