# 稳减 APP 前端焕新完成审计

审计日期：2026-08-09

## 1. 正确性与数据可信度

- 训练页已显式引入 `activityTypes`，五个主页面会在模块级与真实浏览器中实际执行渲染。
- 新用户的饮水、步数、睡眠、运动消耗、餐次和趋势从零开始；首次设置流程不会注入演示记录。
- 热量口径固定为 `剩余可摄入 = 每日预算 - 已摄入`；运动消耗独立展示，不加回饮食预算。
- 目标体重和目标腰围必须分别低于当前值；字段级错误会保留其余输入并聚焦首个错误字段。
- 体重、腰围和任务进度统一限制在 0–100%。
- 数据结构升级为 `schemaVersion: 3`；v2 迁移保留真实记录与偏好，移除 `baseBurned` 和旧演示趋势。

## 2. 设计系统与应用框架

- 视觉令牌采用墨蓝 `#102A3A`、主绿 `#0B715B`、信号绿 `#16A77D`、暖白 `#F2F0E9`、能量橙 `#D86B24`，圆角分为 12/20/28px。
- CJK 使用本地字体栈；Barlow Condensed 以自托管 WOFF2 使用，数据统一启用等宽数字。
- 已移除伪手机状态栏；同步状态进入页面标题栏，并保留安全区与 PWA standalone 配置。
- 样式已拆分为 tokens、base、components、pages；启动骨架、空状态、Toast、确认弹窗与全屏设置页均使用统一组件语言。
- 页面、面板、进度与图表动效只使用 transform/opacity，时长使用 180–240ms 令牌，并通过 `prefers-reduced-motion` 降低动画。
- PWA 应用壳缓存已升级到 v10，自动化验证安装后可以离线重新打开。

## 3. 页面体验

- 首页聚焦体重、剩余预算和今日三件事，身体/饮食/训练提供统一快速入口。
- 饮食页以自然语言 AI 输入和四餐时间线为主，高级份量与营养字段默认折叠。
- 训练页首屏展示今日训练与本周节奏，支持快速记录、历史列表与删除撤销。
- 数据页只读取真实日记录，不足两天显示明确空状态；趋势包含日期范围、文字摘要和可访问说明。
- 我的页突出目标、账号和数据主权；健康指标标注估算依据及“非医疗诊断”。
- 登录和首次设置具备密码显隐、字段错误、加载状态和无演示数据流程；登录页会在提交前区分配置、可达性、Auth 就绪和注册开关。开发环境还提供显式本机账号兜底，线上默认关闭且不会伪装云同步。

## 4. 渐进式架构

- 前端使用显式 ES Module `export/import`，不再使用 `globalThis.FitnessApp`。
- 状态拆分为领域、会话/同步、纯 UI 三个切片；兼容 facade 保持迁移期间现有调用稳定。
- 逻辑、渲染、同步和动作分离；根节点事件委托只注册一次，输入事件不会触发整页重绘。
- 保留 hash 主导航，并提供 `#settings` 路由、返回键恢复和弹窗焦点约束。
- Supabase 状态接口和单状态记录结构保持不变，本轮没有引入 React 或数据库拆表。

## 5. 真实 AI 营养接口

- 仅支持文字输入，请求继续使用 `POST /api/ai/nutrition`，并发送 `locale: "zh-CN"` 与结构化 context。
- 成功响应覆盖请求编号、模型来源、总置信度、复核标记、假设、警告和逐项营养/置信度。
- 错误响应统一处理 `error/code/retryable/requestId`；界面覆盖空闲、识别中、成功、需复核、限流、离线和服务失败。
- 真实模型失败不会回退本地规则；手动输入会保留。
- 保存餐次会记录 `nutritionSource: "manual" | "ai"` 和 AI 结果是否被用户修改。

## 6. 自动化验收

- `npm run check`：语法、schema 迁移、热量口径、目标边界、趋势、AI 契约和模块级五页渲染。
- `npm run test:e2e`：15 个真实 Chromium 测试，覆盖认证不可用、本机账号切换与关闭注册、启动骨架、五页三种数据状态、320×740 / 390×844 / 430×932、字段语义、44px 触控目标、键盘焦点、减少动态效果、登录/首次设置、三类记录、离线同步恢复、AI 全状态、PWA 离线应用壳和视觉回归。
- 九张可重复视觉基准位于 `tests/visual/__screenshots__/`。
- 最终门禁命令为 `npm run verify`。

## 7. 本轮明确不包含

深色模式、拍照/相册识别、社交功能、React 重写、数据库拆表和多设备冲突合并均按计划保留到后续专项。
