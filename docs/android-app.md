## 构建与安装

需要 Node.js 22、JDK 21、Android SDK Platform 36 和 Android Studio/命令行工具。项目位于中文路径时，`android/gradle.properties` 已允许 Gradle 使用该路径。

```powershell
npm.cmd ci
npm.cmd run android:apk
```

调试安装包位于 `android/app/build/outputs/apk/debug/app-debug.apk`。将 APK 复制到手机并允许该来源安装，或连接设备后运行：

```powershell
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

应用包名为 `com.wenjian.healthledger`。覆盖安装时保留应用数据；卸载时系统可能删除应用私有数据，所以请先导出备份。调试包使用本机构建环境的调试签名，正式分发前需要单独配置并保管发布签名。

## 备份、迁移与功能边界

“我的 → 数据管理 → 导出数据”会调起系统分享菜单，请将 JSON 备份保存到手机文件夹或其他由你控制的位置。“导入备份”可以在首次建档页和“我的”中使用，导入前显示记录数量并要求确认。导入会替换手机当前记录；建议先导出当前数据。

已有网页本机账号的数据可在网页“我的”中导出，再把 JSON 文件传到手机后导入。账号密码不会导入。数据格式沿用当前 `schemaVersion: 3`，保存时继续遵守 180 个记录日和体重、腰围各 90 条的保留范围。

这个安装版的建档、手动饮食/训练/身体记录、趋势和本地提醒可独立运行。饮食页可拍照或从相册选择照片，照片不会随记录保存。

## AI 识别与云同步（1.1）

首次建档页和“我的”提供“AI 与云同步”。在这里登录或注册云账号；默认服务地址可在“高级：云服务地址”中查看。服务地址必须是独立部署的 HTTPS 根地址。连接失败、账号过期或断网时，手机档案仍可使用。

首次连接时，如果两端都有档案，默认先检查并停止覆盖。用户可选择保留手机档案或云端档案；应用先在手机保存双方副本，再执行选择。“导出首次同步前副本”可以取回这些数据。后续同步复用服务端版本号、冲突合并和同步期间新修改的处理逻辑。清空手机数据会断开云账号，同时清除本地记录和首次同步副本；它不会删除云端记录。导入备份也会断开云账号，重新连接时再次确认数据来源。

连接后，可在饮食页拍照、选相册或输入文字识别，核对食物和份量后保存。AI 接口只在用户点击识别时发送餐食内容；照片不进入 SQLite、备份或同步内容。DeepSeek 密钥仅在后端。应用中的访问令牌只保留在内存，续期使用 Android 原生 HTTP 的 HttpOnly Cookie。原生日志已关闭，避免插件把 Cookie 写进调试日志。

应用通过原生 HTTP 请求后端，不需要开放跨域 CORS。暂停同步会清除这部手机的登录会话并保留手机记录；重新连接只能使用原绑定账号。切换账号前需导出并清空手机档案，避免误传到另一账号。

构建时可通过 `VITE_API_ORIGIN` 设置默认后端地址，APK 中只包含公开地址，不应设置任何 `VITE_*` 密钥。安装 1.1 时使用同一签名覆盖安装，无需卸载 1.0。

### 后端部署条件

- Render 运行此工作区对应的新版 Node 后端，关闭 `LOCAL_AUTH_ENABLED`。
- 配置可用的 `SUPABASE_URL`、`SUPABASE_ANON_KEY` 和仅服务端使用的 `SUPABASE_SERVICE_ROLE_KEY`。
- Supabase 已应用 `202606300001_init_app_states.sql`、`202609060001_explicit_app_state_grants.sql`、`202609210001_nutrition_budget.sql`，确认表权限、RLS 与预算 RPC。
- 配置 `NUTRITION_AI_ENDPOINT`、`NUTRITION_AI_API_KEY`、`NUTRITION_AI_MODEL`、`NUTRITION_AI_PROTOCOL=deepseek`，并把 `NUTRITION_AI_ALLOWED_USER_ID` 设置为实际使用者的云账号 ID。
- `NUTRITION_AI_MONTHLY_BUDGET_CNY=100` 为既有上限；每个发送请求先预留 ¥0.10，失败也保留额度。预留额度不等于服务商实际账单。

### 2026-09-26 验证边界

本地原生模式测试覆盖登录、手机上传、照片识别与核对、离线重开、续期失败、首次覆盖确认及副本、异账号拒绝、SQLite 写入失败、并发编辑和 409 版本冲突。另以“100 克熟米饭”测试了真实 DeepSeek 文字接口，返回真实模型结果与有效营养数值，预算累计预留 ¥0.10；这不代表已验证真实餐食照片识别准确度或服务商账单。

现有公网 `/api/readiness` 仍返回旧版访问密码错误（HTTP 401）。本地 Supabase 探测返回 `AUTH_PROJECT_NOT_FOUND`，服务角色配置和云平台管理凭证尚未就绪。安卓接入代码和安装包不等于公网服务已恢复；真实云账号、真实跨设备同步、手机相机与通知仍需在后端部署及连接手机后验收。
