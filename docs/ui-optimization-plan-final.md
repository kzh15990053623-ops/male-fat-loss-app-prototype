## 1. 最终结论

两份原文的核心方向成立：产品应从“精密实验室”转向“有数据依据的私人健康手账”，保留纸色背景、墨青、信号绿和 Barlow Condensed 数据字体，同时降低英文装饰、大面积实心卡片和指令式文案的密度。

但两份文档都不能直接作为执行清单。第二份是对第一份的评审报告，不是独立方案；它纠正了部分事实，却也已经被当前工作树反超。最终执行以当前源码和自动化测试为事实源，不再依赖易漂移的文件总行数或截图印象。

本方案采用渐进式五批路线：先校准确定性问题，再统一品牌语言和页面节奏，随后增加情感反馈、图表交互与工程门禁。首批不改认证、数据模型、同步逻辑或服务端合同。

工程边界：

- 原生 ES Module + 分层 CSS，不引入前端运行时框架。
- 浅色主题为当前唯一主题；深色模式不在本轮范围。
- 保持 320–430px 手机视口可用、44px 触控目标、safe-area 和离线能力。
- 不修改认证边界、Supabase RLS、营养 AI 合同、持久化 schema 或服务端 API。
- 所有动画必须在 `prefers-reduced-motion: reduce` 下可靠降级。
- 视觉基准必须先审阅差异，再有意更新；禁止用批量更新掩盖回归。

## 3. 设计方向

### 3.1 核心概念

“安静、有温度的私人健康手账”：既不是医疗后台，也不是游戏化打卡器。用户首先看到今天可完成的小行动，其次看到趋势和长期目标。

### 3.2 视觉原则

1. 纸色负责呼吸，墨青负责结构，绿色只强调进展和主要行动，橙/红只表达真实风险。
2. 深色或高饱和大卡每页最多一个视觉锚点，其他信息使用实色纸白卡、留白、分隔线和轻阴影组织。
3. 数据数字保留 `--font-data`；中文正文使用现有 CJK 字体栈。英文只保留必要单位、模型标识和数据缩写。
4. 普通辅助正文最小 12px；装饰性缩写不得承担唯一信息。正文在实际背景上至少满足 WCAG AA 4.5:1。
5. 动效服务于状态变化：页面切换、完成、保存、加载、图表选点；不为静态装饰持续运动。

### 3.3 文案原则

- 事实优先，不命令、不评判、不暗示补偿性节食。
- 例：“立即记录”改为“记一笔”；“仍有空间”改为“已经过半了”。
- 超出计划时使用中性事实：“今天比计划多 X kcal，明天照常记录即可。”
- “数据已安全保存在本机”只能在本地持久化确认成功后出现。
- 去实验室化必须覆盖页面标题、登录/首次设置、HTML title/meta、manifest、README 和测试，不能只替换五个标题。

## 4. 分批实施路线

### P0a · 确定性组件校准（已完成，2026-08-19）

范围：

1. 将正文 token `--muted` 从 `#65747b` 调整为 `#5f6b70`；`--muted-2` 保持装饰用途。
2. 设置页原生 22px checkbox 保留原生语义，视觉改为纯 CSS switch，覆盖 checked、focus-visible、disabled 和 reduced-motion。
3. 删除训练周计划“今日”行与 hero 重复的“套用计划”操作，保留唯一主入口，并以非交互标记维持周计划节奏。
4. 增加回归断言：训练页只有一个套用入口；switch 可聚焦、可用键盘切换、保存后保持；关键正文颜色满足目标对比度。
5. 审阅训练、设置及受 `--muted` 影响的视觉差异后，只更新意图内基准。

验收：

- `npm.cmd run check` 通过。
- 相关 DOM/E2E 用例通过；视觉失败只来自上述意图内变化。
- `npm.cmd run verify` 最终全绿。
- 320/390/430 无横向溢出，设置 switch 的整行标签仍提供至少 44px 点击区域。

执行结果：

- `--muted` 已调整为 `#5f6b70`，自动断言确认在两档纸色上均达到 AA。
- 设置提醒已改为保留原生 checkbox 语义的 switch；滑钮只使用 `transform` 动画，符合现有合成动画门禁。
- 训练页只保留 hero 的唯一“套用计划”操作，周计划今日项改用非交互绿色标记。
- 新增 2 个 DOM 回归用例；视觉基准已按当前完整工作树重新生成并人工复核训练页、设置页。
- `npm.cmd run verify` 最终结果：17/17 Playwright 测试通过，语法、数据模型、认证就绪、本机认证、营养 AI 合同和应用回归检查全部通过。

### P0b · 可读性与组件层级（已完成，2026-08-20）

范围：

1. 按“正文、辅助正文、单位、装饰眉题”分类审计所有小字号，不做无差别全局替换。
2. 用户必须阅读的辅助文本计算字号不得低于 12px；单位可紧凑，但不得成为唯一标签。
3. 半透明通用卡片改为 `--paper-2` 实色与克制的 `--shadow-soft`，边框主要表达选中、危险或交互状态。

验收：

- 五页 empty / partial / full 三数据态无截断、遮挡或横向溢出。

执行结果：

- 通用卡片改为 `--paper-2` 实色与轻阴影；空态移除 dashed 工程占位，并复用现有记录/导航操作作为唯一主行动。

- empty / partial / full × 五页 × 320/390/430 的渲染、字号和横向溢出门禁通过；axe serious/critical 为 0。

### P2 · 反馈、加载与完成时刻（已完成，2026-08-20）

范围：

1. 把现有 `.app-surface` 淡入限制到真实 Tab 切换，避免普通字段更新或 toast 重渲染重复入场。
2. 盘点仍无 loading/disabled/aria-busy 的异步按钮；复用一套 spinner 和文案规则。

4. `navigator.vibrate?.(10)` 仅作为可选增强，能力检测失败不得影响主流程。
5. AI 取消操作只有在引入 AbortController、迟到响应丢弃和草稿保留测试后落地。
6. 首页 hero 数字使用 400ms 原生 count-up，连续记录强化为可辨识徽章；reduced-motion 直接显示终值。

验收：

- reduced-motion 下无明显位移、缩放或持续闪烁。
- 重复点击不会产生重复记录；加载、成功、失败、取消均有可访问状态。

执行结果：

- `.app-surface` 仅真实 Tab 变化添加入场类；toast、字段和普通状态重渲染的计算动画名为 `none`。
- 设置保存、清空数据、手动同步和退出完成 disabled / `aria-busy` / spinner / 动词文案，并以 singleflight 或 pending guard 阻止重复请求；运动记录增加短时草稿指纹防重。
- 三项任务由未完成变为完成时提供局部回弹、live 文案和安全振动；全部完成弹出可跳过、焦点受控、按用户每日最多一次的庆祝层。
- AI 已接入 AbortController、请求序列和草稿指纹；取消、较早响应、等待期间编辑三类竞态均不会覆盖当前草稿。

### P3 · 同步状态与数据图表（已完成，2026-08-20）

同步状态先定义完整七态矩阵：

| 状态 | 含义 | 建议文案 | 视觉 | 操作 |
|---|---|---|---|---|
| idle | 未登录/未开始 | 等待登录 | 灰 | 无 |
| connecting | 正在建立会话 | 连接中… | 橙色呼吸点 | 无 |
| saving | 本地已写入，正在提交 | 保存中… | 橙色呼吸点 | 无 |
| online | 云端确认完成 | 已同步 | 绿点 | 可选查看时间 |
| device | 本机账号成功持久化 | 本机模式 | 蓝灰点 | 无 |
| local | 本机成功、云端待同步 | 已存本机，等待同步 | 橙点 | 真按钮“重试” |
| offline | 读取/连接失败 | 当前离线 | 灰或红，按错误类型 | 真按钮“重试” |

不得在未捕获本地写入异常时笼统承诺“数据安全”。可点击状态必须使用真实 `<button>`，支持键盘和清晰焦点。

图表范围：

- 折线数据先从纯数值升级为 `{ date, value }`，再实现触摸/鼠标/键盘统一选点。
- tooltip 包含日期、数值、单位，并提供屏幕阅读器等价文本。
- 不引入运行时图表库；描边动画必须有 reduced-motion 降级。

执行结果：

- 七态文案、点色、忙碌状态和真实重试按钮全部落地；本机写入异常被捕获并与网络/服务失败区分，不再作未经确认的保存承诺。
- 本地与云端同步采用单飞请求；本地失败时仍可尝试云端，双端失败与“云端成功但缓存失败”均有诚实状态。
- 体重/腰围折线改为 `{ date, value }`，鼠标移动、触摸点击、键盘焦点和方向键均可选点；tooltip 与 aria-live 同时提供日期、数值和单位。
- 折线描边动画在 reduced-motion 下直接完成，数据点维持至少 44px 可达区域。

## 5. 执行与验证协议

每个原子切片按以下顺序验收：

1. 记录改动前 `git status --short`，只触碰本切片列明的文件。
2. 运行 `npm.cmd run check`。
3. 运行相关 Playwright 用例；视觉用例先允许失败并审阅 actual/diff。
4. 只有差异属于意图内变化时，运行针对性的 `--update-snapshots`。
5. 运行完整 `npm.cmd run verify`。
6. 再次检查 Git 状态和 diff，分别报告已验证、未验证、阻塞项。

禁止：清理工作树、重置用户改动、批量格式化无关文件、自动提交、直接更新全部快照。
