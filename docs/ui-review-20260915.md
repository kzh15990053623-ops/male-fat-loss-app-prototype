# 稳减：UI 与产品体验审阅

日期：2026-09-15

## 结论

当前界面的主要短板是信息取舍和视觉层级：功能入口反复出现，深色渐变、圆环、圆角卡片和阴影占据大量注意力；紧缩粗数字与密集小字进一步强化了仪表盘感。产品虽然叫“私人健康手账”，实际页面仍像一份功能展示板。

建议以“克制、清晰、有生活感的健康手账”为改版方向，先重整首页与饮食记录流程，再统一五页视觉。工程上已有页面模块、设计变量、状态管理和回归门禁，可以沿用这些基础实施。

同时复现了两个影响记录可信度的问题，应列入第一批修复。

## 一、优先修复的产品问题

### 1. P1：只填食物文字保存，会覆盖旧餐次并写入零营养

**已在浏览器复现。** 测试样本原有晚餐 520 kcal，当日总摄入 1560 kcal。保持默认晚餐选项，只输入“一碗米饭和一个鸡蛋”，不识别、不展开营养细节，直接点击“保存本餐”：

- 原晚餐被覆盖，热量和三大营养全部变成 0。
- 当日总摄入变为 1040 kcal，已记录餐次从 3 / 4 变为 2 / 4。
- 内部餐次状态是“已记录”，概览却显示“待记录”；餐次明细不展示刚输入的食物文字。

根因涉及三个相互叠加的设计：营养输入默认折叠且标成“可选”；保存直接赋值覆盖当前餐次；展示用热量是否为 0 判断是否记录。

**改进：** 明确区分新增与编辑已有餐次；保存前展示食物、餐次和营养摘要。营养尚未确认时应要求补充或进入明确的待补充状态，不能把未知值当成已确认的零值。实际零热量记录也应与“未记录”区分。

位置：[饮食表单](../src/render/pages/diet.js) 第 41、62 行；[保存动作](../src/actions/meal.js) 第 74–95 行；[餐次展示](../src/render/shared.js) 第 57–80 行。

### 2. P1：首页趋势的时间范围与计算不一致

**已在浏览器复现。** 只保留 2026-06-01 的 90kg 与 2026-08-09 的 86.2kg 两条记录，首页仍显示“近 7 天”“较上周 -3.8 kg”。

实际算法取最近最多七条记录，计算最后一条减第一条，没有按自然周或七天窗口筛选。数据页使用“近 7 次记录”较准确，但趋势解读又把首尾差描述为“体重均值正在下降”，代码并未计算两段均值。

**改进：** 先统一统计口径。保留现算法时应显示“最近 N 次记录”、实际起止日期和“较首条记录”；若产品需要周环比，应按日期划分可比较的时间段，并处理缺测。均值文案必须对应真实均值计算。

位置：[首页趋势](../src/render/pages/home.js) 第 140–166 行；[数据页](../src/render/pages/data.js) 第 17–26 行；[趋势解读](../src/app-logic.js) 第 574–596 行。

### 3. P2：关闭 AI 后，饮食页仍然保留 AI 主视觉和引导

**已在浏览器复现。** 关闭 `aiAssist` 后，识别按钮消失，但 AI 圆标、“识别后所有数值都可以修改”和 AI 服务说明仍然存在；手动营养字段继续折叠。

**改进：** 手动模式展示“记录这一餐”和直接可用的营养输入；启用辅助识别时，在记录流程内提供识别入口。首页“文字识别”的快捷入口说明也应随设置变化。

位置：[饮食页](../src/render/pages/diet.js) 第 8–41、176 行；[首页快捷入口](../src/render/pages/home.js) 第 62 行。

## 二、“AI 味重”的具体来源

以下属于设计判断，依据是当前源码与实际界面。

### 4. 首页信息过多，重复入口缺少主次

390×844 视口、完整样本、模拟已同步状态下测得：

| 页面 | 页面总高度 | 关键观察 |
| --- | ---: | --- |
| 首页 | 2372px | 9 个主要区块；“现在记录”从约 720px 开始，体重趋势约 1679px，快捷补记约 1851px |
| 饮食 | 2279px | 输入表单约 501px 高；常用餐约 1251px，餐次明细约 1413px |
| 训练 | 1867px | 周计划约 507px 高；快速记录运动从约 857px 开始 |
| 数据 | 2010px | 首屏先展示今日指标和解读，主要图表靠后 |
| 我的 | 1702px | 身体指标、目标、健康估算、预算建议与数据管理连续堆叠 |

首页已有“今日三件事”入口，又出现“现在记录”、教练操作按钮和“快捷补记”；饮水同时存在于任务、指标卡、建议和补记区。教练与每日复盘还重复显示同一个标题，例如“今天还差一点”。

**改进：** 每页确定一个首要任务。首页优先提供当天状态和记录入口，趋势仅保留一个摘要，建议只出现一条最相关内容。饮食中的“今日餐次”与“餐次明细”合并为可展开的餐次列表；训练的整周安排默认收起。

位置：[首页结构](../src/render/pages/home.js) 第 20–82 行；[训练结构](../src/render/pages/training.js) 第 33–35 行。

### 5. 重复装饰占据了视觉层级

- 首页深蓝渐变、同心圆、进度环叠加，周完成率在顶角和圆环重复显示。
- 健康指标在纸白、深蓝、浅橙之间切换；教练、训练和趋势解读又用大块绿色渐变。
- 普通容器广泛使用 20–28px 圆角和大范围阴影，与重要内容竞争注意力。
- 深色底部导航、激活底色、顶端短线与投影叠加，在所有页面都很抢眼。

**改进：** 以一种中性底色承载大部分内容，强调色集中用于主操作与明确状态。普通列表靠间距和细分隔线组织；重要摘要才使用容器。缩小圆角种类，阴影主要服务于浮层的空间关系。底部导航减轻背景和选中态的视觉重量。

位置：[视觉变量](../src/styles/tokens.css) 第 39–48 行；[首页装饰](../src/styles/pages.css) 第 8–28 行；[指标色块](../src/styles/pages.css) 第 376–397 行；[教练卡](../src/styles/pages.css) 第 453 行；[底部导航](../src/styles/components.css) 第 107–166 行。

### 6. 字体系统偏密、偏硬，缺少阅读节奏

当前 Barlow Condensed 粗数字大量用于数据、单位组合和小型统计；标题、按钮、标签也普遍较粗。中文辅助文案继承 `.eyebrow` 的英文大字距设置，小字与粗数字形成较强反差。

**改进：** 建立清楚的四层字号与字重：页面标题、区块标题、正文、辅助信息。数字采用易读的等宽数字特性，单位降低权重但保持可读；中文说明使用自然字距。正文与间距可以作为第一轮视觉样板重点，先在首页和饮食页确定实际效果。

位置：[字体变量](../src/styles/tokens.css) 第 47–49 行；[标题与眉题](../src/styles/base.css) 第 78–98、223–231 行。

### 7. 文案仍然经常面向开发者说话

| 当前文案或内容 | 建议处理 |
| --- | --- |
| 登录后继续读取你的真实进度，不展示演示数据 | 改为“继续记录你的进步” |
| 我们不会为新账号填充演示记录 | 首次设置直接解释“填写基本信息，用于估算每日预算” |

## 三、建议采用的页面结构

| 页面 | 优先呈现 | 后续层级 |
| --- | --- | --- |
| 今天 | 日期、今日摄入与剩余预算、明确的记录入口 | 当天记录、一个趋势摘要、一条相关建议 |
| 饮食 | 今日营养摘要、早餐/午餐/晚餐/加餐列表 | 点击餐次进入记录或编辑，常用餐贴近输入入口 |
| 训练 | 今天的参考安排、记录运动 | 今日记录；周计划与训练类型可展开 |
| 数据 | 体重或腰围主图、明确的时间范围和单位 | 饮食与运动趋势；简短的数据解读 |
| 我的 | 个人信息、当前目标、设置列表 | 指标估算与数据管理按需进入 |

视觉方向：暖白或低饱和中性色、深色正文、单一克制强调色；更充分的留白与统一对齐；少量圆角容器；朴素、清晰的图表与状态反馈。图表应在未选点时也提供必要的日期与数值参照，保留现有触摸、键盘选点及文本数据视图。

建议先完成首页和饮食页的可操作样板，确认排版、表单、列表、导航和不同数据状态后，再扩展至训练、数据和我的页面。

## 四、工程上值得补强的地方

### 8. P2：320px 窄窗口出现横向滚动，现有断言会漏报

在本轮 Windows Chromium 的经典滚动条环境中，30 个场景均能渲染且没有 `NaN` / `undefined`，但其中 9 个 320px 场景有横向滚动；390px、430px 未发现此问题。320px 空数据的数据页未出现，因为页面没有产生纵向滚动条。

根因是 `html` 与 `body` 强制最小宽度 320px，纵向滚动条占用可用布局宽度。现有测试用 `window.innerWidth` 判断溢出，漏掉了滚动条占用的宽度。

**改进：** 依据实际可用布局宽度设计，并用 `document.documentElement.clientWidth` 等布局尺寸检查溢出；分别覆盖经典滚动条和移动设备环境。这个复现结论适用于本机窄窗口，尚未据此认定真实手机必然出现相同问题。

位置：[根布局](../src/styles/base.css) 第 7–17 行；[现有断言](../tests/dom/app-dom.spec.mjs) 第 136 行；[复现截图](../output/playwright/review-20260915-diet-320.png)。

### 9. P3：样式维护可以随改版进一步分层

五页渲染已经拆分，但 `pages.css` 有 2048 行，`components.css` 有 1321 行。建议随实际修改按页面拆分样式，补充间距、字号和字重变量，并明确哪些组件可复用。范围以改版涉及的页面为准，沿用现有 ES Module 与事件委托架构。

回归测试应补上本次复现的文字保存、已有餐次覆盖、AI 关闭、稀疏称重记录、窄窗口溢出场景。视觉验收先看真实截图差异，再定向更新受影响的基准。
